# 라벨 품질 이슈

> 공개용 합성 기록입니다. 셀 ID·수치는 실제 값이 아닙니다.

## 발견 경위

학습 데이터를 늘린 seg-v3 모델이 홀드아웃에서 오히려 나빠졌고, 특히 결함 위치 정확도
(Localization)가 31%로 무너졌다. 모델을 더 손대기 전에 라벨부터 확인했다.

라벨 면적 분포가 두 봉우리로 갈렸다. 작은 실제 기공과, 이미지 면적의 25~50%를 덮는
대형 사각 블록이었다. 셀 ID별로 나눠 보니 대형 라벨이 특정 셀 9개에 몰려 있었다.
기공이 아닌 다른 구조가 기공(porosity) 클래스로 잘못 매핑된 것으로 판단했다.

해당 셀 ID: **208, 209, 210, 211, 212, 213, 214, 219, 223**

## 검증 실험

**모델 구조와 학습 설정은 그대로 두고**, 위 9개 셀의 오라벨 이미지를
**학습 데이터에서 제외해 다시 학습**했다.

평가는 두 모델 모두 **같은 홀드아웃 셀 6개 · 380장**으로 했다. 이 6개 셀에는
오라벨 셀이 하나도 없으므로 **평가 데이터는 바뀌지 않았다.**

| 항목 | 오라벨 포함 학습 | 오라벨 제외 재학습 |
|---|---|---|
| F1 (conf 0.05) | 0.651 | 0.798 |
| Localization 정확도 | 31% | 72% (다른 에폭에서 83%) |

구조와 설정을 한 줄도 바꾸지 않고 학습 데이터에서 틀린 라벨만 뺐는데 F1이 0.147 올랐다.
즉 이 구간의 성능 저하는 모델 구조의 문제가 아니라 정답(라벨)의 문제였다.

## 후속 조치

9개 셀 ID를 데이터팀에 전달해 다음 버전 전처리에서 클래스 매핑을 고치도록 요청했다.

## 교훈

문제의 위치를 세 번 옮긴 셈이다.

1. 처음에는 **모델**을 의심했다 → 구조와 하이퍼파라미터를 바꿨다
2. 다음에는 **지표**를 의심했다 → 동분포/홀드아웃을 분리하고 운영점을 재정의했다
3. 마지막에 **정답(라벨)**을 의심했다 → 여기서 가장 큰 개선이 나왔다

성능이 오르지 않을 때 모델만 계속 바꾸면 시간을 가장 많이 쓰고 가장 적게 얻는다.

## 남은 문제

학습 데이터 활용률이 용량 대비 약 21.4%에 머물렀다. 축 밀도 불일치가 원인이며
재추출이 필요한 상태로 프로젝트가 종료되었다. 재추출 시 성능이 추가로
올라갈 여지가 있으나 검증되지는 않았다.
